# ARTEX 补丁验证
来源方法：Trail of Bits post-patch-validation，CC BY-SA 4.0，提交 82fe8226252622fa807643bdca1710901198553a。
只用于已存在的补丁、修复提交或补丁文件；没有补丁时不要把此流程用于一般复测。
验证对象是本地源码，不执行远端或生产目标。测试代码须获授权后才能运行。

## 固定输入
读取原 finding、根因、前提、原始复现记录和合法行为要求。
固定易受影响基线与补丁输入，优先使用不可变提交；不在用户工作树应用补丁。
检查变更文件、调用者、同类路径、错误处理、清理逻辑和既有测试。
通过实时可用工具 schema 选择隔离副本/容器；不把运行者权限误认为沙箱。
没有隔离能力或运行代码授权时，降为源码/构建证据并明确限制。

## 对照检查
先证明控制用例可在基线和补丁均运行。
原漏洞断言应在基线失败、补丁通过；确认失败确由断言触发，不是构建或导入错误。
为相同根因选择至少一个不同触发形态或相邻入口验证变体。
检查未受影响的正常行为、定向回归和邻近的新安全问题。
安全检查的基线也要通过，才能把补丁侧失败归因于新引入的问题。
分别保存命令、输入、版本、原始标准输出/错误输出和退出状态。
若工具提供固定环境或隔离运行计划，按其 schema 使用；不得伪造检查已执行。
不为验证补丁而改写补丁或削弱断言；失败结果交回修复方后固定新输入重跑。

## 判定
区分源码、构建和实际运行证据等级；源码/构建通过不能证明运行行为。
有效结果必须能归因于被测代码，工具失败或缺少触发标记属于证据缺口。
记录发现、缺口、行为变化、清理状态和人工复核要求。设计覆盖时参考[证据模型](references/evidence-model.md)。设计覆盖时参考[证据模型](references/evidence-model.md)。
结论只覆盖本次固定版本、测试环境和检查集，不保证其他版本或部署安全。
