# ARTEX 源码上下文构建
来源方法：Trail of Bits audit-context-building，CC BY-SA 4.0，提交 82fe8226252622fa807643bdca1710901198553a。
适用：ARTEX 0.3.15 worker 或 pentest 的本地源码分析；这是静态源码工作，不是黑盒 Web 渗透。

## 目标
建立代码如何工作、依赖什么、哪些假设未被保障的可查记录。
不在本阶段命名漏洞、评级、编写 PoC 或宣称影响成立。
若已有 finding，只为理解其相关调用链和证据缺口，不代替验证或复测。

## 方法
先确定仓库/版本、目标组件、入口函数和安全边界。
按函数记录输入、输出、必须成立的条件、调用者和被调用者。
沿调用链查看检查在哪里发生；不能仅凭函数名或注释认定检查已执行。
追踪条件分支、错误路径、状态变化、权限决策和敏感操作。
说明每项假设由哪处代码支撑；找不到保障时明确记为未发现。
保留相互矛盾的源码观察和未解问题，不强行合并成确定结论。
每条源码主张写相对路径、函数和行号；路径或修订不确定时注明。
输出模块概览、函数契约、跨模块规则、关键依赖和待查问题。参考模板：[分析记录格式](references/ANALYSIS_FORMAT.md)、[函数分析示例](references/FUNCTION_MICRO_ANALYSIS_EXAMPLE.md)、[领域注意事项](references/DOMAIN_NOTES.md)。
使用平台当下可用的本地源码读取/搜索能力；按实时工具 schema 操作。
不要执行源码或测试，不修改目标仓库，也不连接网络目标。

许可证与出处：[Trail of Bits CC BY-SA 4.0](references/TRAIL-OF-BITS-LICENSE.txt)。

## 边界
静态源码只说明代码结构，不证明运行实例加载该版本或外部入口可达。
保留用户范围，只查看理解目标所需的最少相关调用链。
在后续动态验证中，重新确认授权、目标版本、控制组和清理计划。
