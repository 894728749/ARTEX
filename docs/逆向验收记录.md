工具链路验收使用 `TestReverseRealEngineAcceptance`：通过 API 创建逆向草稿、上传材料，动态路径先确认默认拒绝、再明确授权；随后调用注册工具与真实引擎，保存完整证据，在另一条意图复核，检查已采纳状态及报告中的 SHA256。此测试验证平台链路与证据约束，不代表任意模型都能独立完成任意逆向问题。

三平台正常结束和实际取消均验证了脚本卸载、会话分离、自有进程终止及暂存清理；Android 额外验证本次 APK 卸载。运行记录校验平台、材料和脚本摘要，未确认清理或脚本报错的结果不得记作成功证据。

真实模型联合验收另外暴露了三处平台问题：逆向白名单漏了 `get_worker_output`；部分 REA 的 JSON 字符串结果无法逐层分页；Frida 默认 `console.log` 输出会污染运行器的 JSON 响应。修复后，三个平台均重新执行包含 `console.log` 的真实工具链路并通过，日志被保存在证据消息中。另在写图前拒绝将材料编号传作 `asset_ids`，避免错误锚定或外键异常；长文本支持按 Unicode 字符分页。

联合验收使用真实 `deepseek-flash` 模型，在 12 分钟任务预算内自行分析四个样本、生成三个目标并执行 9 次动态观察（6 次成功，3 次失败后已取得对应平台的成功结果）。该轮最终 **0/3 目标完成**：结论仍在独立核验或修正阶段；.NET 结论因复核提出 IL 定位分歧而被拒绝，没有被计为成功。该拒绝理由本身也不能直接当作已确认的代码错误（需注意十进制偏移与十六进制 IL 标签的区别）。该结果保留为自动流程的失败记录，不能用实际引擎测试通过替代，也不代表一般复杂逆向任务能在同样预算内自动收敛。

修复后的定向真实模型复验使用同一 `deepseek-flash`，仅提供自制 .NET 材料及 Frame 字符串构造/null 分支问题，没有预写目标、结论或核验答案。模型自行规划、读取 REA 完整 IL、提交结论，再由不同意图读取两份原始结果并接受结论，最后成功 `prove_goal`，**1/1 目标完成、工具错误 0**。额外检查结论包含 Trim、ToUpperInvariant、Concat 和 ArgumentNullException，证据文件存在且非错误结果，报告含材料 SHA256。该结果证明本次有界问题的自动闭环，不能覆盖前述联合任务未完成的部分。

兼容性边界：REA 6.8 使用 Ghidra 12.1.x，本次固定为 12.1.4，官方压缩包 SHA256 为 `ddac49f903da9d5bac833e5cc79395098b9c33cfd3279be5f31bd00387d2d4db`。Ghidra 12.2 被版本检查明确拒绝，未绕过检查。Android 9 曾出现 Java Hook 可见性和全局去优化兼容问题，不能视为已通过的系统版本；本次完成的 Android 动态验收是 Android 15。没有把这些样本结果扩展为所有系统版本、架构或程序类型的兼容保证。
