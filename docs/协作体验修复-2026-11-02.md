# ARTEX 协作体验修复

基于 `cyy081021/ARTEX` 的 `5c0dbd4bec940f3c0faf20705a56d879b57d3dfe`。本次修改在独立源码目录完成；实现和验证阶段没有替换正在运行的旧版 ARTEX，也没有修改其业务数据库。源码发布状态以 Git 提交记录为准。

## 行为变化

| 需求 | 实现 |
| --- | --- |
| 报告跨设备阅读 | Reporter 增加自包含要求，保存报告时检查明确的平台编号引用、本机文件链接及执行机路径。标题不加序号，证据按用途引用。保留真实目标路径、API 参数、CVE、版本和复现步骤编号。检查失败要求重新写，不自动删改证据。 |
| 运行中引导 | 主 Agent、Worker 和任务外会话可在执行中继续发送消息。每次运行有独立消息队列；当前工具继续运行，下一次工具执行前处理引导。模型直接结束回答时也检查队列。Worker 的 request_id 在本轮内去重；无法接收时明确报错。 |
| 温和停止整个任务 | `pause_after_tool` 先禁止新规划和排队 Worker 领取任务，当前工具调用返回后取消后续轮次，不等待整个 Worker 完成。结果及会话历史保留；未完成意图退回队列，任务保持暂停，恢复后继续。保留立即暂停，并允许从温和暂停升级为立即暂停。 |
| 漏洞归类检查 | 新增 `finding_reviewer`，默认每 3 个新发现检查一次，阈值可调为 2–20，也可手动检查。判断具体根因、组件、条件及修复边界，不按标题、类别或等级直接合并。仅影响范围扩展不应重复登记。 |
| 整体漏洞报告 | 确认为同一漏洞时，原记录和证据保留为内部审计，普通列表与统计只显示统一记录。合并资产及证据绑定，增加证据版本，持久化排队调用 Reporter 重写报告。对外按一个完整漏洞描述。旧报告保持可查但标为待更新；过期证据版本不能覆盖新报告。 |
| 漏洞关联图 | 新增“漏洞关联”页，显示前置条件、提供能力、证据支持、证据矛盾。每条边包含理由、证据及待验证/已验证状态；支持人工增删、访问漏洞详情和文字列表。依赖链禁止循环，有直接或间接依赖的候选不能被直接归并。 |
| 范围收起 | 任务总览超过 5 条范围时默认折叠，显示数量，并可展开全部或收起。 |
| 操作约束“规则” | `allow / deny / rule` 贯穿数据库、API、Agent 工具、目标解析和前端编辑。规则以独立段落注入，不冒充允许或禁止。 |

## 归类与报告的边界

- 检查员只有读取本批漏洞证据、归并、记录关系、完成检查四类工具；不能执行命令、调用其他工具或联网搜索。可以读取同一任务已绑定的证据正文。
- 关系的“已验证”表示已有证据支持关系本身。仅有可能性时保留“待验证”，不能因高低等级推测利用链。
- 归并事务校验所属任务、候选状态和证据版本，并保留原始快照。归并过程中的分页不会因记录隐藏而跳过后续条目。
- 同一任务同一时刻只有一个归类批次。失败批次不原地反复自动调用模型；新发现或手动检查可触发后续处理。报告重写失败在页面显示，可通过手动检查重试。
- 升级时为历史任务建立水位，避免首次启动就自动把全部历史漏洞发给模型。旧漏洞可以手动触发检查；旧报告不会被启动迁移直接改写。
- 归档包保存新增关系、归并审计和报告重写记录；恢复会保留统一记录及其来源。新增数据库表不影响旧归档缺少这些表时的恢复。
- “当前工具”以 ARTEX/SDK 的一次工具调用为单位。若工具自身启动长时间运行的命令，温和暂停会等该调用返回；要立即打断时使用立即暂停。
- 引导队列属于正在运行的进程，不承诺进程崩溃后自动重放尚未注入模型的消息。正常结束时未处理的消息会明确提示；用户消息另有活动记录。

## 验证

使用 WSL Ubuntu 的 Go 1.26.3 和独立 PostgreSQL 实例（本轮专用端口 55439），测试仅使用本地模拟模型、虚构目标和保存的测试证据。

已通过：

- 真实 SDK 会话配合模拟 Provider：当前工具完成后暂停、结果保留、不执行下一工具或模型轮次；工具边界和最终回答边界的引导处理、顺序及去重。
- HTTP/控制集成：运行中的 MainAgent、Worker、任务外会话接受引导；主会话分段隔离；温和暂停持久化、禁止排队任务领取、工具未结束时拒绝恢复。
- 数据库与 API：归并事务、跨任务拒绝、证据版本冲突、普通列表/导出/任务统计排除来源记录、原始审计、证据绑定复制、陈旧报告拒绝、关系循环拒绝。
- 自动检查批次阈值、并发去重、水位、失败与手动重试；规则 CRUD 和提示词分组。
- 新增归档往返测试：统一漏洞、来源记录、关联、审计、报告队列恢复；统一记录删除无孤儿来源。
- 前端 TypeScript 检查和 `next build --webpack`；Go 全包编译、后端构建和 `git diff --check`。

完整测试 `go test -p 1 ./...` 未全绿：

- `TestGraphOverviewExpandsAssociatedCompanyScope` 报 `task scope missing`，在未修改的基线提交和独立数据库中也复现。
- 一次 `TestTaskMetadataPatchReturnsRenameAndPin` 在 `TempDir` 清理时报目录非空；其业务断言未失败，基线单独运行通过。该完整测试运行存在未结束后台任务的日志，不能据此宣称整个测试套件通过。

未进行真实模型的归类质量评估、正式环境部署或完整浏览器手工验收。自动归类仍取决于模型对已有证据的判断，应关注不确定关系和报告重写错误。构建环境复用已有依赖目录的符号链接；默认 Turbopack 因外部符号链接失败，本轮用 webpack 构建通过。

## 部署说明

前后端需要一起更新。数据库迁移随服务启动执行，并播种可配置的漏洞归类 Agent；实际运行需要为它和 Reporter 配置可用模型。旧版运行实例尚未加载本次修改。

构建方式沿用仓库原有流程：Go 后端 `go build ./cmd/artex`；前端静态导出可使用 `NEXT_EXPORT=1 next build --webpack`，然后按仓库已有的 `embedui` 发布流程打包。部署前保留数据库和现有程序备份，选择没有正在执行任务的时段更新。
