# 团队消息与执行端标识

团队工作区可查看已共享任务的主 Agent、Planner 和 Work 消息。任务会话列表中的 Work 标注「本机」或「设备 #编号」；远程 Work 打开后使用同一共享消息面板。

消息层包含用户文字、Agent 中间说明和最终答复，不返回思考记录、工具参数、工具结果或活动元数据。成员仍须具备任务的 `read` 权限；向正在执行的 Work 发送引导还须具备 `execute` 权限。此功能不授予全局任务、配置或其他团队的访问权。

## 消息交付

- 主端保存用户消息后显示「待交付」。远程消息绑定工作单及 epoch；旧页面不能把引导误发给重新分派后的执行端。
- Node 在工具调用边界接收引导。当前工具可完成，后续动作须考虑引导。消息交付不表示模型已经按要求完成工作，应查看后续回复和证据。
- 同一 `request_id` 重试去重；同一设备事件序号不能改写已保存的文字。设备保存本地消息日志，传输故障不会自动重放工具。
- 本轮封口与引导写入在同一工作单锁下互斥；封口时已有待交付引导会阻止封口。结束后不再接受新引导，未交付消息明确显示状态。
- 页面按消息编号增量补取并去重；分页加载历史与补取新消息使用不同游标，不依赖 SSE 单点连通。

## 本机与远程并发

每任务 Worker 数仍控制本机 Worker 池；设备运行器按自身容量领取工作，远端不占用本机 Worker goroutine。任务级全局名额用于本机自动规划/执行准入。

当一个任务只剩远端派发、远端执行或待独立复核，且没有本地可运行工作、在途本地操作或现有主 Agent 会话时，协调端释放本机名额。持久队列模式 `remote_resume` 仅阻止本机自动工作；远端领取、续租、消息和结果仍须满足原有身份、任务状态、权限、租约和 epoch 检查。

复核或其他操作产生本地工作后，任务重新按 FIFO 获取名额。用户暂停、终态任务、权限撤销、普通准入队列均不会因这个例外获得远程执行权。用户主动开启的主 Agent 对话继续保留原先独立于自动 Planner/Worker 暂停的行为。

## 兼容与验证

Hub 的数据库变更仅新增消息表、索引及工作单消息状态字段。新 Node 声明 `message_protocol: 1` 后，新派发工作单才启用消息交付；旧 Node 仍执行原有工作单，界面会明确显示消息通道未开放。

升级时先更新 Hub 再更新 Node。含 `remote_resume` 的活跃任务不应在运行中回退至不认识该队列模式的旧 Hub；应先让该轮完成或明确暂停。

隔离 PostgreSQL 回归覆盖消息权限、跨任务边界、最终答复投影、工具与思考排除、分页补取、重复请求、旧 epoch、封口、远端续租、本机名额释放及结果返回后的重新准入。Node 使用本机假模型和工具夹具验证交付，并以实际 Node 子进程连接 TLS 协调端和隔离数据库，检查最终消息及封口。结束时收到新指导的续跑路径也覆盖文本去重。上述测试不代替两台物理设备的网络验收。
