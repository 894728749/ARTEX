# 本地配置 profile 同步

`profiles/local-team/` 保存显式导入用的 Agent/MCP 配置快照与 information_checker 网关。profile 不含数据库连接、任务记录、运行日志、凭据值或服务启动步骤。导入只改配置表，不创建或启动任务。

## 导出当前 runtime

在 WSL 中运行。`ARTEX_CONFIG` 指向当前本机 runtime 配置文件；`--integration-root`、`--skill-source`、`--collector-source` 显式指定网关源文件。命令只读查询数据库，psql 输出仅写入 profile，不把凭据或源配置打印到终端。

```sh
ARTEX_CONFIG=/path/to/runtime/config.json \
python3 scripts/profile_sync.py export \
  --psql /path/to/postgres/bin/psql \
  --pg-lib /path/to/postgres/lib \
  --integration-root /path/to/integrations \
  --skill-source /path/to/ARTEX-0.3.15/skills/artex-windows-privacy-audit \
  --collector-source /path/to/windows_privacy.ps1
```

profile 导出 Agent 启用状态、当前完整 prompt 和变量、LLM 配置名/绑定、MCP 启用状态与工具缓存、逐 agent MCP/单工具绑定、Skills 可见性、完整触发设置、工具启用状态与 agent 绑定。模型 API key 和 MCP env 密钥只输出环境变量占位。私有 IP、目标域名、任务编号和本机绝对路径会被清理；Skill 与网关源码一并复制，运行数据目录不复制。

## 安装 / 恢复

先准备目标 ARTEX PostgreSQL 数据库和运行时配置，然后显式指定数据库名和确认目标。导入器应用仓库 `db/schema.sql`，并在一个事务中按稳定 key/name 幂等恢复 profile。导入前须备份目标库。

默认不导入 LLM profile，保留目标库已有模型设置；Agent 绑定会按模型名称映射到目标库中已有配置，未匹配时保留既有绑定或在新 Agent 上留空。需要一并恢复 profile 中的非凭据模型参数时加 `--include-models`，并为 profile 中列出的 API key 环境变量提供值。MCP 密钥、私有 MCP URL、命令路径等占位同样须通过环境变量提供；缺少占位值时导入在写库前失败。

```sh
ARTEX_CONFIG=/path/to/runtime/config.json \
python3 scripts/profile_sync.py apply \
  --psql /path/to/postgres/bin/psql \
  --pg-lib /path/to/postgres/lib \
  --profile profiles/local-team/profile.json \
  --database <目标数据库名> --confirm-target
```

默认省略 `--include-models`，以保留目标库当前模型配置；Agent 会按模型名称绑定到目标库已有配置。只有明确要复制 profile 中的模型非秘密字段时才添加 `--include-models`，并先确认已为所有模型 API key 占位设置环境变量。profile 的 `is_default` 仅在 `--include-models` 时恢复。

## 占位变量与网关运行

查看占位名：

```sh
python3 -c "import json,re; d=json.load(open('profiles/local-team/profile.json',encoding='utf-8')); s=json.dumps(d,ensure_ascii=False); print('\\n'.join(sorted(set(re.findall(r'\\$\\{([A-Z][A-Z0-9_]*)\\}',s)))))"
```

MCP URL、API key、env secret 和绝对命令参数按服务器名生成 `ARTEX_MCP_<NAME>_*`；LLM key 按 profile 名生成 `ARTEX_LLM_<NAME>_API_KEY`。通用私有值占位（如 `${PRIVATE_HOST}`、`${PRIVATE_IP}`、`${ARTEX_SECRET}`、`${TASK_ID}`、`${ARTEX_INSTALL_PATH}`）是供人阅读的说明文本，导入时不会要求设置同名环境变量。配置变量应放入部署环境的 secret store，不写进 profile 或 Git。

profile 中的网关代码位于 `gateway/integrations/tools/`，Skill 位于 `gateway/skills/`。部署时将 integrations 内容复制到目标 runtime 的 integrations 目录，将 skills 内容复制到目标 ARTEX 的 skills 目录；不要覆盖已有同名 Skill 前先做备份。以 WSL runtime 为例，在仓库根目录执行：

```sh
export ARTEX_RUNTIME_ROOT=/path/to/runtime
export ARTEX_INTEGRATIONS_ROOT="$ARTEX_RUNTIME_ROOT/integrations"
export ARTEX_SKILL_DIR=/path/to/ARTEX-0.3.15/skills
mkdir -p "$ARTEX_INTEGRATIONS_ROOT" "$ARTEX_SKILL_DIR"
cp -a profiles/local-team/gateway/integrations/. "$ARTEX_INTEGRATIONS_ROOT/"
cp -a profiles/local-team/gateway/skills/. "$ARTEX_SKILL_DIR/"
```

随后将以下环境变量写入启动 information_checker MCP 进程的运行环境（Windows collector 路径使用 PowerShell 可识别的路径；WSL 下通常是 `/mnt/<盘符>/...`）：

- `ARTEX_RUNTIME_ROOT`：ARTEX runtime 根目录，用于读取本地 JWT key 和访问 API。key 本身不复制。
- `ARTEX_INTEGRATIONS_ROOT`：部署后的 integrations 根目录。
- `ARTEX_API_BASE`：本机 ARTEX API 地址，默认 `http://localhost:8787`。
- `ARTEX_PRIVACY_COLLECTOR`：部署后的 PowerShell collector 文件路径。
- `ARTEX_POWERSHELL`、`ARTEX_WINDOWS_INTEGRATIONS_ROOT`、`ARTEX_WINDOWS_CURL`、`ARTEX_WINDOWS_NODE`：WSL/Windows 桥接路径。
- `ARTEX_PRIVACY_CHROMIUM`：隔离 Chromium 可执行文件。
- `ARTEX_INSTALL_PATH`：仅当 profile 的 MCP 命令参数中出现 `${ARTEX_INSTALL_PATH}` 时，提供对应安装路径。导出的 Windows collector 源码不含该占位。

另外需按本机平台安装 MCP Python SDK、Node.js、Playwright、Chromium 及其系统库，并按需配置 integrations 下的 Playwright modules/browsers。profile 不带可执行浏览器二进制、runtime `jwt.key`、任务证据或报告目录。导入不会自动启动 Agent、MCP 或任务。

## 隔离验证

可先在空测试库上显式执行 apply，再检查 Agent/MCP/触发器/可见性/工具绑定的行数和名称映射。不要对生产数据库做 profile 验收；实际部署应由操作者在目标库备份后明确运行命令。
