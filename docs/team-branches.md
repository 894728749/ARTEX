# 共享主任务与执行分支

此模式显式启用，沿用现有团队、设备配对和 LAN 优先 / Relay 回退传输。旧任务仍使用原来的本机调度或单工作单交接；旧节点不会自动得到新分支。主端执行时也应配对一个独立节点，使用相同的范围、预算和权限规则。

## 对象与执行

主任务保留统一目标、资产版本、材料哈希、权限与总预算。工作池条目描述一个资产范围内的问题、必要角色、验收标准和预留额度。成员选择自己的设备认领；认领事务原子建立同一主任务下的分支，不复制任务或数据库。重复点击返回已有分支；其他成员并发认领失败。

分支持有独立上下文、工作单、操作记录和本地日志。节点配置完整时自动就绪，随后在多轮 Planner → 执行单元 → 技术核验之间推进。条件不足时保留待就绪原因。Planner 使用对应工作流的独立提示词及本机模型绑定；渗透角色为 worker/reviewer，逆向角色为 reverse_static/reverse_dynamic/reverse_reviewer，不进行跨工作流角色兜底。

工作单保留 `db.WorkContract`，绑定角色、假设、验收条件、依赖和资源键。执行结果须明确给出 candidate/blocked/failed，候选结果不是已接受结论。技术核验单元必须覆盖所有有效执行单元。随后由没有参加执行的另一名授权成员复核。阴性结论可以完成一个问题；分支验收不会自动完成主任务。负责人明确关闭主任务，未完成时必须选择部分完成并填写缺口。

工作池中的 `coordinator:true` 分支用于主 Planner 的资产覆盖与工作提议。它读取按权限裁剪的工作池和进度，提出待批准工作；`auto_publish` 允许其在既定范围和总额度内直接发布。它自身也必须认领到节点并计账。普通分支不能发布任意团队工作。

## 权限与指导

新增模式分别授予 read、process、evidence、discuss、execute、guide、control、review、manage；旧团队 read/execute 仍是上层边界。只读访问不等于执行或控制。受限分支进一步限制成员范围。

快照、事件回放、实时流、搜索、导出与材料下载复用服务端权限检查。实时流逐批重新验证身份和权限；撤权后不再发送新批次。已下载的内容不会被远程收回。模型凭据与设备私有路径不进入可移植策略；节点在上传输出前按本机秘密值规则脱敏。

讨论只进入共享消息。明确发送的指导才进入执行队列，显示 queued → received → applied，失效指导显示 failed。分支有唯一控制负责人，接管、暂停、转交、复核等使用控制修订号避免旧页面覆盖新控制状态。项目暂停且全部当前操作结束后，管理者才可扩展资产范围或增加总额度；旧资产版本和已用额度保留。

## 预算、互斥与恢复

额度以获准的模型请求和工具/规划动作次数计数，不是金额或 Token。创建工作预留主任务额度，重试与转交不重置已用次数；跨流程协助从来源分支的剩余额度划出。单次工具、模型和工作单另有墙钟时间限制。

同一团队的不同主任务共享资源键。工具操作还为同一资产目标和动态 profile 建立互斥键；与旧式本地/远程工作单声明的资源键检查冲突。`min_tool_interval_ms` 限制共享资源的工具启动间隔。它不限制一个外部工具内部产生的请求数；HTTP 请求频率仍需由本机工具适配器或代理实现。

节点在操作前先持久记录，再获取当前服务端授权；授权无法确认时不启动下一操作。当前有界工具可以结束并保存证据。服务端记录开始但结果未知的操作持续占用互斥资源，不靠租约过期直接解锁。恢复时补传持久命令与证据，不重放外部副作用。

温和暂停停在工具边界，立即停止要求节点取消正在进行的调用。转交保留原分支及历史，等待旧端确认停止；无法确认时明确展示转交等待。人工确认旧执行端已停止必须填写原因，然后推进执行代次；旧代次不能继续续租或提交新状态。未知/失效/失败工作通过显式 `supersedes` 新建补充验证单元，保留原记录，不自动重跑未知操作。

动态授权绑定设备的 profile ID、摘要、平台、时限、材料哈希和具体工作单。每个授权只允许一次 `reverse_observe_runtime`；重试、换端或新工作单需要新授权。

## 跨流程与证据

`assist` 生成相反工作流的关联工作，来源分支等待其独立验收。协助不反向依赖尚未完成的来源分支，依赖图拒绝循环。协助的 `workflow_request_id` 使用既有 workflow 请求的 ID 序列，但持久化在 `team_branch_workflow_requests`：旧 `workflow_requests` 专用于不同任务之间的协助，其过期调度不能误驱动同一主任务内的分支。取消来源分支会取消未完成的下游协助，原预算与审计仍保留。

跨分支引用包含 branch_id、unit_id、证据版本。来源撤回或变化会使引用单元和下游验收失效，要求补充核验；已完成的主项目重新变为暂停。逆向解释只能作为有来源的候选说明，原渗透问题仍需自己的行为验证。

归档保存项目、事件和协助归属。恢复只恢复审计历史，不恢复旧租约、设备令牌、运行授权或活动分支。由于恢复环境的成员/设备可能不同，完整分支归档历史只向管理员展示，不能根据旧 ID 自动恢复成员访问权限。

## 节点与 API

参考 `examples/team-node-branches.example.json`。`execution.branches.enabled` 默认为 false；本机应分别配置 planner/reverse_planner 和需要的执行角色。模型密钥仅从节点环境变量读取。外部命令/MCP 能力必须同时被主任务角色、工作单和设备角色授权，并配置 `branches.scope_fields`，把工具的目标字段约束到分支资产。应用层字段校验不等同于操作系统沙箱。

主要接口：

- `POST /api/teams/{team}/tasks/{task}/branches/enable`：已共享、已暂停且无活动旧执行的任务显式启用；body 包含 policy、可选 artifact_ids 和 role_capabilities。
- `GET .../branches`、`/events`、`/stream`、`/export`：一致权限的快照和游标事件页；导出/搜索需循环获取 has_more 的后续页。
- `POST .../branches/command`：认领、管理、讨论、指导和复核；request_id 保证幂等，控制操作带 revision。
- `GET /api/collaboration/device/branches`、`POST .../branches/{task}/{branch}/command`：设备自己的分支与有代次约束的执行命令。
- `GET .../branches/{branch}/materials/{sha256}`：每次最多 4 MiB 的明确 Range，节点校验全量大小和 SHA-256。

启用后，旧任务聊天、意图执行与调度入口拒绝启动第二条不计入分支预算的执行链。共享分支界面用于该模式的讨论、指导和控制。原任务数据和全局 Agent/MCP 配置不因启用而被覆盖。

## 验收边界

测试使用独立 PostgreSQL、多个身份和逻辑节点、TLS 本地服务、假模型与合成材料。真实节点子进程测试覆盖持续规划、材料回传、角色隔离和独立复核；状态与数据库测试覆盖认领竞争、预算、互斥、撤权、代次、故障恢复、动态授权、证据失效和归档。另使用真实 API 的隔离页面进行浏览器验收。具体命令及当次结果记录在工作区验收报告；不能将本机通过等同于第二台物理设备或生产网络验收。
