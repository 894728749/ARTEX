# ARTEX 独立逆向任务

创建任务时选择“逆向分析”。任务以暂停草稿保存，在“分析档案”上传材料，再启动。历史任务和未传 `kind` 的客户端继续创建渗透任务。

静态分析使用 REA 6.8.0：JavaScript（`.js`、`.mjs`、`.cjs`）走应用图，APK 走 JADX 清单、组件、类/方法与引用，.NET 走元数据、成员与 IL，原生 PE/ELF/Mach-O 走 Ghidra 反汇编、伪代码与调用关系。托管程序按 PE CLI 目录识别，不能仅凭 `.exe` 后缀判断。页面分别显示各引擎就绪状态，不应把工具目录存在视为能力已经验证。

## 本地安装

当前验收环境为 Windows 上的 WSL Ubuntu。使用 npm 安装固定版本，不运行 REA 的交互式 setup，不修改其它 Agent 的 MCP 注册：

```sh
bash scripts/install-rea.sh /absolute/path/to/artex/tools
```

安装目录位于 ARTEX 可执行文件旁的 `tools` 时自动发现。也可以指定 `ARTEX_REA_COMMAND`；需要包装启动命令时，`ARTEX_REA_ARGS` 为 JSON 字符串数组，默认 `["mcp"]`。专用 Node 版本从启动器所在目录优先解析。未安装时“分析档案”明确显示引擎未就绪。

APK 需安装 [JADX Headless MCP 0.7.1](https://github.com/1013503897/jadx-headless-mcp/releases/tag/v0.7.1)，设置 `REA_JADX_MCP_JAR`。原生分析需安装 [Ghidra 12.1.4 官方发行版](https://github.com/NationalSecurityAgency/ghidra/releases/tag/Ghidra_12.1.4_build)，设置 `GHIDRA_INSTALL_DIR` 和符合其要求的 `JAVA_HOME`（JDK 21）；REA 6.8 接受 12.1.x，不能直接替换为 Ghidra 12.2。这些变量由启动 ARTEX 的进程继承；本机路径与引擎二进制不纳入仓库。.NET 元数据和 IL 使用 REA 自带解析器。

启用 application、session、android、managed、native、direct、artifact 工具族，并提供完整输入 schema。另设静态工具白名单，上游工具族注册不会自动开放 shell、任意进程附加或设备安装能力。每个 Worker 独立启动 stdio 实例，按工作单懒连接，不与其它 Worker 或就绪检查共用会话。分析前核对工件大小和 SHA256，原始上传文件与分析副本分开保存。

## 分析与验收

1. 初始目标分解：围绕用户问题拆成少量证据可验证的目标。
2. Planner 创建有合同、依赖与预算的分析意图；Worker 用 `reverse_workspace` 读取材料，并通过 `rea_catalog` 读取真实参数、`rea_analyze_artifact` 或 `rea_call` 分析。
3. `reverse_submit_conclusion` 保存候选结论、工件定位、直接观察、原始结果引用及局限。候选解释保持 `proposed`，不会自动成为已证明目标。
4. Planner 为其安排另一条核验意图。核验者重新读取材料与证据，调用 `reverse_review_conclusion` 接受、驳回或记录未决。系统拒绝同一意图自行核验；检查工件归属、SHA256、原始结果路径和当前核验工作状态。
5. 只有已接受结论对应的事实节点才可用于逆向任务的 `prove_goal`。调查元数据或候选结论的提交回执可完成工作单，但不能证明用户问题已经得到回答。
6. 分析档案展示材料、结论、证据与核验状态，支持材料、原始证据和 Markdown 档案下载。没有工具、材料或新方向时保留阻塞及恢复条件。

完整返回的 MCP result（包括 `structuredContent`）保存在任务 `reverse/results`；模型仅收到有限预览。对大输出需要通过 REA 的分析视图继续分页或保存导出的 Evidence bundle，不能把预览当作全部程序证据。REA 会话内 `evidence_id` 在 Worker 结束后不保证有效，后续工作必须读取已保存证据或重新打开材料。

暂停沿用当前工具结束后暂停及立即停止路径。立即取消向 REA 发送取消通知并终止该工作单拥有的进程，WSL/Linux 同时终止其进程组。静态工作流不提供通用 shell 或运行样本能力；动态观察使用下述独立授权工具。Worker 每次最多 16 轮、12 分钟，并受更小的任务/工作单预算约束；Planner 每轮最多 12 轮。

## Windows、Linux、Android 运行时观察

`reverse_observe_runtime` 调用独立 Frida 运行器，保存实际调用、输出、脚本错误、材料/脚本 SHA256、观察窗口和清理结果。默认拒绝执行材料。管理员配置环境后，用户暂停逆向任务，在“分析档案 → 运行时观察”选择环境、可运行材料和时长上限，保存后再启动任务。

在运行器所在系统创建 Python 3.11+ 虚拟环境，安装 `frida==17.23.2`；按实际路径修改 `scripts/reverse-runtime-profiles.example.json`，删除没有配置的环境，设置 `ARTEX_REVERSE_RUNTIME_PROFILES` 指向私有 JSON 文件。最多配置 16 个环境。运行命令、远端地址及路径映射由管理员提供，模型不能选择任意 PID 或启动命令。

Windows ARTEX 可直接配置 Windows Python。WSL ARTEX 也可配置 `/mnt/c/.../python.exe`，参数使用 Windows 脚本路径；`path_mappings` 可映射共享材料目录，例如 `[{"from":"/mnt/e","to":"E:"}]`。路径映射不会向其它设备复制材料，远程设备调度属于后续协作范围。

Android 使用专门的可 root 实验模拟器、同版本 frida-server 和 ADB forward；配置 `remote.address`、`adb_serial`、独立 `adb_port`、`aapt`。运行器核对 APK 包名，拒绝覆盖同名已有应用，仅安装本次材料；结束时终止自有进程并卸载本次安装的包。Java Hook 需安装 `frida-java-bridge@7.0.13` 并配置 `java_bridge_module`，由 Python Frida Compiler 与观察脚本一起构建。可选 `java_interpreter: true` 仅对本次新装包设置 `verify` 编译模式，写入运行证据。优化、系统版本和触发路径会影响 Hook 可见性，零次命中不等于逻辑不存在。

观察窗口为 100–60000ms，同时受用户更小上限约束。单次脚本最大 128KiB，最多保留 1000 条消息/输出、约 2MiB 观测数据，超限明确标记截断。运行器只启动本次材料，不附加已有用户进程；取消时请求卸载脚本、分离会话、终止本次样本及清理暂存，超时标记清理未确认。进程分离不是操作系统沙箱，实际权限由管理员提供的虚拟机、容器或实验主机控制。

## 数据与兼容性

`tasks.kind` 与 `workflow_version` 持久化并固定；材料、结论、运行授权和观察记录分别持久化。工件使用任务工作空间相对路径，上传文件名仅作标签，单文件限制 256MiB。归档包含逆向表及任务目录；恢复保留类型、材料、核验者和原始证据，但关闭运行授权，原未完成观察记为失败，需用户重新确认本机环境。旧归档缺少类型字段时保留现有渗透类型。

`testdata/reverse` 提供自制 C、Go、C#、Android 样本源码。显式设置 `ARTEX_REVERSE_ACCEPTANCE_SPEC` 后运行 `go test -v ./server -run '^TestReverseRealEngineAcceptance$'`，覆盖上传 → 默认拒绝/授权 → 真实引擎 → 原始证据 → 独立复核 → 报告；普通单测不执行上传文件。spec 包含 `workspace` 和 `cases`，各项指定 `name`、`artifact`、`expected`；动态项另指定 `profile`、`script`、`duration`、可选 `package`；静态深入项指定 `static_tool`、`static_args`，其中 `path:"$artifact"` 替换为本任务材料路径。

渗透与逆向的跨任务委托、小团队权限、跨设备执行以及 LAN/Relay 通信不在本阶段实现范围，等待用户检查本阶段后继续。
