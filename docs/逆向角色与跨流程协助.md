# 逆向角色与跨流程协助

创建任务时确定 `pentest` 或 `reverse`，运行中不切换任务类型。两条流程各自维护模型绑定、提示词版本、预算、工具配置、会话及任务目录。共享实现代码不意味着共享 Agent 配置。

## 逆向角色

| Agent key | 职责 | 默认单轮预算 |
| --- | --- | --- |
| `reverse_main` | 用户对话、问题、材料与范围管理 | 12 轮、600 秒 |
| `reverse_goals` | 将用户问题转为有证据标准的目标 | 8 轮、300 秒 |
| `reverse_planner` | 按需分配工作、安排核验与处理委托 | 12 轮、600 秒 |
| `reverse_static` | JS、APK、.NET、原生材料静态分析与候选结论 | 16 轮、720 秒 |
| `reverse_dynamic` | 在本任务已授权环境进行运行时观察 | 16 轮、720 秒 |
| `reverse_reviewer` | 独立读取材料和证据，接受、拒绝或保留未决结论 | 16 轮、720 秒 |

角色按需运行。工作合同的 `execution_role` 决定具体执行者，再加载该角色的模型和配置；禁用或缺失的角色不会借用渗透 Worker。历史上没有角色字段的逆向工作按静态角色处理。动态观察可以直接回答已知入口的运行问题，不必为此重复完整静态分析。

系统 Agent 页面分别编辑这六个角色。主提示词、预算收尾词、任务超时收尾词均使用各自的配置键。内置工具的逆向配置保存在 `reverse__<tool>` 名下，实际调用名仍为原工具名。修改渗透工具的启用情况、说明或缺省参数，不会修改逆向副本。首次升级补建缺少的配置，后续启动保留用户修改。

静态角色没有动态执行工具；分析角色不能写核验结果，核验角色不能提交候选结论。同一意图不能核验自己的结论。内置 Read、LS、Glob、Grep 限制在本任务目录，阻止绝对路径越界及外部符号链接读取。材料、事实、原始引擎结果和结论仍是不同记录。

MCP 和 Skill 的可见绑定按角色分别配置。若主动将同一 MCP 服务或模型连接绑定给多个角色，其服务配置、外部额度和底层资源仍是共同依赖；平台级资源不构成进程或虚拟机隔离。逆向运行权限始终由接收任务自己的 runtime policy 决定，复制材料不会复制执行权限。

## 发起协助

任务详情中的“跨流程协助”可以查看收到和发出的请求，创建请求或取消自己发出的待处理请求。请求包含具体问题、验收条件、预算和选定输入。

- 渗透任务可选择已有逆向任务，或选择文件后自动创建独立逆向协助任务。
- 逆向任务请求实际服务行为验证时，必须选择已有渗透任务，在其原有范围内执行；材料中的地址不会自动产生测试授权。
- 文件路径相对来源任务目录，每次最多 8 个、单个最多 64 MiB、总计最多 128 MiB。复制前后核对 SHA256，接收侧保留来源。
- Agent 可额外选择本任务事实或发现的 ID 和内容版本。只复制所选证据快照，不创建整任务黑板继承关系。
- 已有接收任务处于暂停时，接收请求后继续保持暂停；可通过任务链接查看和恢复。自动新建的协助任务进入正常调度。

Agent 工具为 `request_workflow_help`、`list_workflow_requests`、`return_workflow_result` 和 `cancel_workflow_request`。默认授予两条流程的主 Agent 和 Planner。相同请求重试沿用 `request_key`，不同输入不能复用同一个键。来源任务同时最多等待 8 个请求。

## 结果与状态

请求状态为 `pending`、`completed`、`cancelled` 或 `expired`。结果单独标记 `accepted` 或 `unresolved`，并包含摘要、证据和局限。`completed` 只说明结果已回传，不代表问题已解决。

逆向 `accepted` 回传必须引用独立核验已经接受的结论事实。来源任务收到的结果作为待验证依据写入自己的图谱，不直接证明来源目标，也不自动登记为已确认漏洞。来源 Planner 负责将解释与实际行为验证结合。

等待请求的意图不领取 Worker。开启任务并发限制时，只有等待工作的任务在当前模型调用结束后释放名额，收到结果后按正常队列恢复。接收方还有待回传请求时，即使已证明目标也不会提前完成整个任务。

每个请求预算为 1–3600 秒，截止时间从创建时开始；接收任务暂停或排队也计入。接续请求最多 3 层，子请求共享父请求总预算和截止时间，已完成或取消的子请求预算不返还。后续分析或核验合同应沿用 `workflow_request_id`，系统也会从目标、前置工作及证据来源继承归属。

取消、过期及关联任务删除只停止属于该请求的工作，保留接收任务的其他工作。终态结果不可覆盖；重复发布和重启后补发不会生成重复回传事实。待处理请求会阻止相关任务归档，需先回传、取消或等待过期。

## 验证边界

代码包含配置隔离、独立模型解析、目录读取范围、双向回传、请求去重、预算、超时、取消、删除恢复、等待释放和队列恢复测试。真实引擎验收通过静态或动态角色装配工具，再由独立核验角色读取证据。模型自主分析能否得到正确答案仍取决于材料、问题和模型判断；工具完成不等于目标完成。

此功能是单个 ARTEX 实例内的两类任务协同。跨设备 LAN 优先、Hub 回退的网络设计尚未实现。
