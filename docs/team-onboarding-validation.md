# 跨设备接入向导：更新与验证记录

日期：2026-11-10。本次为 main 分支功能更新，不创建版本 tag。

## 更新内容

- 团队页加入接入向导：检测主端地址、预填网段、预览固定方案、明确确认后开启受限 TLS、下载成员接入包和一次性配对、定期核对设备状态。详细手工 LAN/Relay 配置保留。
- 受管成员 TLS 动态启停，主端任务引擎不重启。启动参数管理的 TLS/Relay 入口保持原有行为。证书和状态安全持久化，端口占用、TLS 检查或写盘失败时关闭新入口。
- AI 用无工具的单次调用解释固定检测事实。拒绝自由日志输入，不发送设备地址、私钥、身份或模型密钥；输出有大小/结构限制，失败时回退固定建议。
- `artex-node setup` 完成证书/版本核验、本地配置、单次配对和身份复用，保留既有配置。可生成渗透或逆向的独立无外部工具角色模板；密钥仅进入进程环境；启动执行需再次明确确认。
- 正式构建新增五种 Node 资源与版本/SHA256 清单。成员包不含配对码、私钥和模型凭据。WSL 的固定桥接脚本默认预览，实际操作限定选定 IP、端口和来源网段。

## 多机验证仍需实测

本次没有第二台物理设备。以下不作为已通过项目：真实 LAN 互通、Windows 主机桥接的实际应用、跨网 Relay、macOS/ARM 的实际运行，以及具体模型/MCP 工具执行。

主端和 Node 必须来自同一个构建，建议构建版本包含提交短号。旧正式版本仅在线替换主程序后，可能缺少新 Node 资源，需安装同版本完整包。成员先完成仅连接验收，再配置模型和明确允许的工具，随后按团队/任务/分支分别授权。具体操作见 [团队接入指南](team-onboarding.md)。
